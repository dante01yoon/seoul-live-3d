# 이슈 분류

## 에이전트가 맡을 수 있는 이슈

| 분류 | 라벨 | 언제 | 다음 단계 |
|---|---|---|---|
| 바로 수정 | `factory:fix` | 증상을 지금 코드로 재현했다. 또는 화면에 무엇을 더할지 이슈에 분명히 적혀 있고 바뀔 파일이 2~3개 안쪽이다 | `/factory-fix <번호>` |
| 스펙 먼저 | `factory:spec` | 화면·데이터 구조를 새로 정해야 하거나, 사람이 고를 선택지가 있다 | 사람이 정한 뒤 다시 분류 |
| 정보 부족 | `needs-info` | 어느 역·어느 시간대·무엇을 기대했는지 없어 재현할 수 없다 | 묻는 댓글 |

## 순서

1. `gh issue list --state open --json number,title,body,labels`로 `factory:`·`needs-info`·`knowledge:flag` 라벨이 없는 이슈를 가져온다.
2. 이슈마다 위 표로 나누고 근거를 한 줄로 적는다.
   - 버그를 「바로 수정」으로 고를 때는 이슈에 적힌 역·시간대로 루트 모듈 함수를 `node -e`로 직접 불러 증상을 재현한다. 재현하지 못하면 「정보 부족」이다.
3. 인자가 `dry-run`이면 표만 보여 주고 GitHub에는 아무것도 쓰지 않는다.
4. 아니면 라벨을 붙인다(없으면 `gh label create`). 「정보 부족」 이슈에는 재현에 필요한 값을 묻는 댓글을 단다. 댓글 첫 줄은 `🤖 팩토리 자동 답변`.
5. 마지막에 `| 이슈 | 분류 | 근거 | 다음 단계 |` 표로 요약한다.
